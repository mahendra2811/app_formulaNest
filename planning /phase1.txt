For the initial phase, I’d build the app as a **small but complete offline-first MVP**. The goal is to finish the architecture and all major user flows with very little sample data first, then scale the content later without changing the app structure.

### Phase 1 goal

Build the full product skeleton with only a small dataset, for example:

- Class 10 → Maths → 2 chapters
- Class 12 → Physics → 2 chapters
- JEE Main → Physics → 2 chapters
- 20–30 formulas
- 10–15 short notes
- 20–30 MCQs
- 2–3 formula sheets

That is enough to test almost every feature.

# Tech stack

For your case, I recommend:

### App
**React Native + Expo + TypeScript**

This fits you well because you already work with React/TypeScript, and this app does not need heavy native functionality initially.

### Navigation
**Expo Router**

Use file-based routing like:

```text
app/
  (tabs)/
    index.tsx
    learn.tsx
    practice.tsx
    search.tsx
    library.tsx

  formula/[id].tsx
  note/[id].tsx
  chapter/[id].tsx
  test/[id].tsx
```

### Local database
**SQLite**

Use:

**expo-sqlite**

Do not use only AsyncStorage for the content database.

SQLite should store:

- formulas
- notes
- subjects
- chapters
- questions
- relationships
- search keywords

This will scale much better when you eventually have thousands of records.

### User preferences

Use either:

**Zustand + AsyncStorage**

for:

- selected class
- selected exam
- selected subjects
- theme
- onboarding status
- small UI preferences

SQLite can store larger user state like test history/revision later.

### State management
**Zustand**

Keep it simple.

You don't need Redux.

Suggested stores:

```text
useUserStore
useContentStore
useBookmarkStore
useTestStore
useSettingsStore
```

### Styling

I would use:

**NativeWind + React Native**

because you're already comfortable with Tailwind-style development.

You can also use a component system, but don't make the UI dependent on a huge library.

### Icons

**Lucide React Native**

### Formulas

Use **LaTeX** as the formula storage format.

For example:

```json
{
  "formula": "v = u + at"
}
```

and for mathematical equations:

```json
{
  "formula": "\\frac{-b \\pm \\sqrt{b^2-4ac}}{2a}"
}
```

Then render using a React Native-compatible math renderer/WebView solution.

This is very important because formulas should **not be stored as images**.

# Recommended content architecture

Your original source files can stay JSON.

For example:

```text
content/
  classes/
  exams/
  subjects/
  chapters/
  formulas/
  notes/
  questions/
```

But during build/import:

```text
JSON
   ↓
validation script
   ↓
SQLite database
   ↓
app
```

This gives you the best of both worlds.

You can easily give me or another AI JSON later, but the final app queries SQLite.

---

# Basic entity design

Start with these tables.

```text
classes
exams
streams
subjects
chapters
topics

content
questions
content_tags

bookmarks
recent_items
revision_items
test_attempts
settings
```

Instead of separate tables for formula/note/theorem, I would initially use a generic `content` table:

```text
content
-------
id
type
title
body
formula
explanation
example
subject_id
chapter_id
topic_id
difficulty
importance
keywords
```

Where:

```text
type =
formula
note
definition
theorem
shortcut
graph
table
```

Then create relationships for class/exam mappings.

This avoids duplication.

---

# Very important relationship model

A content item should support multiple audiences.

For example:

```text
Quadratic Formula
```

may belong to:

```text
Class 10
Class 11
JEE Main
NDA
```

So do not directly put only:

```text
class_id = 10
```

Use mappings:

```text
content_classes
content_exams
content_subjects
```

This architecture will save you a lot of problems later.

# Phase 1 definition of done

I would call the first phase complete when a user can:

> Install app → choose Class 10 → Maths → open a chapter → see formulas → search a formula → read its explanation → bookmark it → add it to revision → solve a few MCQs → generate a small test → share a formula image → close the app → reopen it → everything still works offline.

If that complete loop works with only **30 formulas**, the architecture is ready for **30,000 formulas later**.

### Final recommended stack

```text
React Native
Expo
TypeScript
Expo Router
NativeWind
Zustand
expo-sqlite
AsyncStorage
Lucide React Native
LaTeX-based formula data
JSON → validation/import → SQLite
EAS Build
```

For this app specifically, I would **not use Next.js, Node.js, PostgreSQL, MongoDB, Firebase backend or Supabase in Phase 1**. They add complexity without solving a real problem yet.

Your first milestone should therefore be **“complete offline engine with tiny sample content,” not “complete content database.”** Once that works, we can define the exact JSON schema and then start generating/importing the large Class 6–12 + JEE/NEET dataset.
